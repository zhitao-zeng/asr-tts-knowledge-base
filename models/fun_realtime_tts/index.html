架构细节 · 设计动机与机制

设计动机

面对实时语音交互中“高自然度”与“极速响应”难以兼得的矛盾，阿里 Fun-Realtime-TTS 将语音合成做成端到端流式系统，目标是毫秒级首包延迟下输出接近真人语调的语音，服务于智能汽车、数字人直播、实时翻译与客服等强时效场景。

整体流水线（双流式架构）

采用 bi-streaming（双向流式）设计：文本 token 流入与音频波形流出双向流式并行，文本边到达边生成音频，首包延迟可低至约 128–150ms（据官方报道及 Preview 实测），较传统方案合成速度提升约 5 倍。据推测其主干沿用 FunAudioLLM 家族的 LLM 式 codec 生成路线（文本/说话人条件 → 语义 token → flow-matching 声学头/声码器），并通过流式 chunk 解码与动态注意力控制声调韵律。

关键能力

  • 支持 30+ 语言、7 大汉语方言族、20+ 地区口音，覆盖中文复杂方言语调。
  • 指令跟随控制韵律、情绪与音色（instruction-following prosody/emotion/timbre）。
  • 与同族 Fun-Realtime-ASR、Chat 共享基座，形成三赛道（ASR/TTS/Chat）综合布局。
训练数据与目标 · 配方

数据与训练哲学

闭源商业模型，公开训练配方细节有限。据推测采用大规模多语种/多方言语音数据与指令跟随数据训练，并以 Artificial Analysis Speech Arena 盲测 Elo 为优化目标（即人类偏好对齐），而非单纯追求客观指标。

实时化训练目标

通过动态注意力机制与流式解码约束，训练模型在极低首包延迟下保持声调与韵律正确性；合成速度与延迟被作为显式优化项。
