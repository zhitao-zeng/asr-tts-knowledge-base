架构细节 · 设计动机与机制

双轨 Dual-Track 离散多码本 LM 架构

  • 两个自研 tokenizer：（1）Qwen-TTS-Tokenizer-25Hz 单码本，强调语义内容，用 block-wise DiT 或流匹配做流式波形重建，与 Qwen-Audio 无缝集成；（2）Qwen-TTS-Tokenizer-12Hz 多码本（12.5Hz、16 层 RVQ），极速率、超低延迟。
  • 12Hz 变体采用分层预测：主干 Talker（28 层 transformer、RoPE、GQA）吞入聚合码本特征预测 0 号码本；MTP 多 token 预测模块生成剩余 15 个码本，避免每步跑 16 次全模型。
  • 25Hz 变体用单码本加线性头预测当前 token，再经 chunk-wise DiT 高保真重建。

端到端离散建模与流式

  • 论文强调通用端到端架构：离散多码本 LM 完全旁路传统 LM 加 DiT 级联的信息瓶颈与级联误差，提升 versatility、效率与上限。
  • Dual-Track 流式：文本 token 与声学 token 沿通道轴连接，收到一个文本 token 立即预测对应声学 token，由 Code2Wav 转波形；首包延迟低至 97ms（0.6B）/101ms（1.7B）。

与 SOTA 的本质区别

  • 区别于语义 token 加扩散声学两阶段，Qwen3-TTS 用统一离散多码本 LM 端到端建模全部信息；轻量非 DiT 解码器加 12Hz 极低帧率实现 97ms 首包，是其相对 Qwen-Audio-3.0-TTS（同族前作，12.5Hz tokenizer 加 LM 加 FM 五阶段）的工程飞跃。

数据与三阶段预训练

消融与关键发现

双 tokenizer 取舍

  • 论文经验发现：纯语义 tokenizer 表达力不足，纯声学 tokenizer 注入过多低层细节导致 LLM 长程误差累积；25Hz 融合语义与声学（基于 Qwen2-Audio 编码器）在表达力与可建模性间平衡。
  • 12Hz 多码本加轻量因果 ConvNet 实现 97ms 首包，验证极低帧率对延迟的关键作用。

分层预测 MTP

  • 消融：用 MTP 模块并行生成剩余 15 码本，相比逐码本串行显著降延迟且质量持平，是 12Hz 变体实时性的核心。

对齐策略

  • DPO 加 GSPO 对比无对齐：指令跟随与任务稳定性提升；长上下文扩展（32768）使超 10 分钟长语音 WER 最低。
局限与开放问题 · 批判评估

真实边界

  • 12Hz 极低帧率虽降延迟，但相对高帧率 codec 在极细腻韵律与高频细节上可能有损。
  • 10 语覆盖以主流语种为主，超低资源语种未覆盖；虽 Apache-2.0 开源，1.7B 部署仍需相当算力。
  • 端到端多码本 LM 把全部信息压入离散 token，对可解释的中间表征（语义与声学分离）控制弱于两阶段方案。

批判

  • 大量指标（Seed-TTS 最低 WER、跨语言降 66%）来自其自有评测设置，缺乏与 Fish-Speech S2/MiniMax/ElevenLabs 在统一榜上的逐项绝对值对比，SOTA 需结合上下文看。
  • 25Hz 与 12Hz 双变体定位重叠（均支持流式、克隆、指令），选型指南不足，易让用户困惑。
  • GSPO 作为较新优化器，其相对 PPO/GRPO 的稳定性收益缺乏充分消融披露。
