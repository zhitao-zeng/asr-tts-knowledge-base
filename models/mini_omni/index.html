Mini-Omni

gpt-omni · 2024-08 · 领域 ASR · 参数量 0.5B (Qwen2-0.5B) · 许可 Apache 2.0
一句话

首个开源的端到端实时语音对话模型，文本与语音 token 并行生成，仅 0.5B 参数即可实时交互。

所属主线
LLM / MoE 统一系
关键指标（统一基准）

本模型暂未纳入统一基准对比表。

架构细节 · 设计动机与机制

端到端语音对话

Mini-Omni 是首个开源的端到端实时语音对话模型，输入端可为语音或文本，输出端同时包含文本与语音，无需外部 ASR 或 TTS。

并行生成

通过文本-语音同时生成方案，让已生成的文本 token 指导语音 token，降低直接推理语音的难度，并消除等待完整文本的时间。

组件

以 Whisper-small 为语音编码器、Qwen2-0.5B 为语言骨干、SNAC 多码本方法做语音解码，仅 0.5B 参数。

训练数据与目标 · 配方

三阶段训练

阶段一冻结 LLM、仅训练 ASR/TTS 适配器做模态对齐；阶段二冻结适配器、让模型在音频输入下做文本推理；阶段三整体微调多模态数据。

数据集

引入 VoiceAssistant-400K（GPT-4o 生成、40 万条）用于语音助手微调，并融合 LibriTTS、VCTK、Open-Orca 等数据。

Any Model Can Talk

该训练框架可迁移到任意语言模型，少量参数与分阶段训练即可赋予语音交互能力。

消融与关键发现

解码策略

对比基础并行、文本指导并行与批并行解码，批并行解码借文本推理增强语音质量效果最佳。

文本指导

让文本 token 先出、语音层顺序跟随，可明显降低语音推理错误。

参数效率

0.5B 小模型在保留文本能力前提下实现实时语音交互。

局限与开放问题 · 批判评估

语音精度

纯语音 ASR 弱于专用模型：LibriSpeech clean/other 为 4.5% / 9.7%，高于 Whisper-small 的 3.4% / 7.6%。

语音自然度

音频输出质量与专业 TTS 仍有差距。

规模

0.5B 参数限制复杂推理与多任务深度。

创新点
  • 首个开源端到端实时语音到语音对话模型
  • 文本与语音 token 并行生成消除级联延迟
  • 三阶段训练使任意 LLM 快速获得语音能力
与别家技术差异
vs Whisper

Mini-Omni 端到端语音到语音且实时，Whisper 仅做识别、需外接 TTS

vs Qwen2-Audio

Mini-Omni 端到端语音输出且实时，Qwen2-Audio 以文本输出、非实时

论文逐句解读 · Insight 旁注
To our best knowledge, Mini-Omni is the first fully end-to-end, open-source model for real-time speech interaction.
— arXiv:2408.16725 Abstract

核心创新：首个全端到端、开源的实时语音交互模型，能「听-想-说」流式进行，无需 ASR→LLM→TTS 级联。它把语音对话从级联管线压缩成单一模型，延迟与工程复杂度大幅下降，是实时语音 agent 的重要路线验证。

To achieve this capability, we propose a text-instructed speech generation method, along with batch-parallel strategies during inference to further boost the performance.
— arXiv:2408.16725 Abstract

关键方法：用文本引导的语音生成（用文本模态监督音频生成）配合batch-parallel 推理（文本与音频并行解码）实现实时。仅 0.5B 参数即完成实时对话，证明小模型也能跑通端到端语音，但需文本模态「托底」以保证逻辑一致。

while Mini-Omni's speech recognition performance slightly lags behind Whisper-small's decoder
— arXiv:2408.16725 Section 4

主要局限（诚实写出）：Mini-Omni 的语音识别略落后于 Whisper-small解码器，且「仅音频模态」推理时逻辑一致性弱于文本推理（需 batch 生成弥补）。它是实时端到端的早期验证，音质/识别精度与纯级联方案仍有差距，适合低延迟场景而非最高精度场景。
